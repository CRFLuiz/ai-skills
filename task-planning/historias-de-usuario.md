# Histórias de Usuário e Decomposição

## Princípios INVEST

1. Independente (Independent)
2. Negociável (Negotiable)
3. Valiosa (Valuable)
4. Estimável (Estimable)
5. Pequena (Small)
6. Testável (Testable)

## Estrutura de uma História de Usuário

1. **Título e Descrição:** Como um [tipo de usuário], eu quero [funcionalidade] para que [valor/motivo].
2. **Critérios de Aceite:** Formato Dado que [contexto], Quando [ação], Então [resultado].
3. **Notas Técnicas:** APIs, banco de dados, frontend.
4. **Estimativa:** Pontos de história (Story Points).
5. **Dependências:** O que precisa ser concluído antes.
6. **Prioridade:** Utilizando MoSCoW.

## Decomposição (Épico -> História -> Tarefa)

1. Um Épico é um grande sistema ou funcionalidade.
2. O Épico é dividido em Histórias com estimativas de pontos.
3. Cada História é dividida em Tarefas menores e acionáveis, com estimativa de horas.
