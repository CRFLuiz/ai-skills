# Boas Práticas e Processo

## Princípios Chave

1. Faça apenas uma pergunta de cada vez, evitando sobrecarregar o usuário.
2. Prefira perguntas de múltipla escolha para facilitar as respostas.
3. Remova recursos desnecessários de todos os designs.
4. Explore alternativas, propondo sempre de 2 a 3 abordagens antes de se decidir.
5. Valide o design de forma incremental e obtenha aprovação antes de avançar.
6. Seja flexível para voltar e esclarecer pontos que não façam sentido.

## Documentação e Revisão

1. Escreva o design validado (spec) no caminho `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md` e faça o commit.
2. Revise o documento procurando por placeholders (como "TBD", "TODO"), consistência interna, adequação do escopo e ambiguidades.
3. Corrija quaisquer problemas encontrados diretamente no texto.
4. Solicite que o usuário revise o documento antes de prosseguir com o plano de implementação.

## Companion Visual

1. Ocasionalmente, ofereça um companheiro visual baseado no navegador para exibir mockups e diagramas, caso as perguntas envolvam tópicos visuais.
2. Essa oferta deve ser feita em uma mensagem isolada, sem incluir outras perguntas.
3. Decida para cada pergunta se é melhor usar o navegador (para conteúdo visual) ou o terminal (para requisitos e conceitos em texto).
