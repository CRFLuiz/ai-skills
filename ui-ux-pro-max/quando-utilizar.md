# Quando Utilizar a Skill

Esta skill atua como uma inteligência de design e deve ser usada sempre que a tarefa envolver alterar a aparência, a sensação, o movimento ou a forma de interagir com uma funcionalidade.

## Uso Obrigatório (Must Use)

A skill deve ser invocada nas seguintes situações:
1. Projetar novas páginas (Landing Page, Dashboard, Admin, SaaS, Mobile App).
2. Criar ou refatorar componentes de UI (botões, modais, formulários, tabelas, gráficos, etc.).
3. Escolher esquemas de cores, sistemas de tipografia, padrões de espaçamento ou sistemas de layout.
4. Revisar o código da UI visando experiência do usuário, acessibilidade ou consistência visual.
5. Implementar estruturas de navegação, animações ou comportamento responsivo.
6. Tomar decisões de design a nível de produto (estilo, hierarquia de informações, expressão da marca).
7. Melhorar a qualidade percebida, a clareza ou a usabilidade de interfaces.

## Uso Recomendado (Recommended)

A skill é recomendada nas seguintes situações:
1. A UI parece "não profissional o suficiente", mas o motivo não é claro.
2. Ao receber feedback externo sobre usabilidade ou experiência do usuário.
3. Na otimização da qualidade da UI antes de um lançamento (pre-launch).
4. Ao alinhar o design de maneira multiplataforma (Web / iOS / Android).
5. Ao construir sistemas de design ou bibliotecas de componentes reutilizáveis.

## Quando Ignorar (Skip)

Esta skill não é necessária nas seguintes situações:
1. Desenvolvimento focado puramente em lógica de backend.
2. Tarefas que envolvem apenas o design de API ou banco de dados.
3. Otimização de performance que não esteja relacionada à interface.
4. Trabalho de infraestrutura, servidores ou DevOps.
5. Scripts não visuais ou tarefas de automação isoladas.

> **Critério de Decisão:** Se a tarefa for mudar a aparência de algo na tela, como aquilo se move, como se sente ao toque ou como o usuário interage com a ferramenta, esta skill deve ser usada.
