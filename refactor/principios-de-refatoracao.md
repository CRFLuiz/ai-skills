# Princípios de Refatoração

## As Regras de Ouro

1. **O comportamento é preservado:** A refatoração não altera o que o código faz, apenas como ele faz.
2. **Passos pequenos:** Faça mudanças minúsculas e teste após cada uma.
3. **Controle de versão é seu amigo:** Faça commits antes e depois de cada estado seguro.
4. **Testes são essenciais:** Sem testes, você não está refatorando, está apenas editando.
5. **Uma coisa por vez:** Não misture refatoração com a adição de novas funcionalidades.

## Quando NÃO Refatorar

1. Código que funciona e não será alterado novamente.
2. Código crítico de produção sem testes (adicione os testes primeiro).
3. Quando você está sob um prazo apertado.
4. "Apenas porque sim" - é necessário ter um propósito claro.
